# OTO LINK

音の高さを使って、近くの端末どうしで短いテキストを送受信する実験的な音響モデムです。4つのFSKレーンを同時に鳴らし、1シンボルで4ビットを運びます。

**Live demo:** https://sho36sho36.github.io/oto-link/

## 使い方

1. GitHub Pagesでページを開き、送信側と受信側で同じ合言葉を入力します。
2. 受信側で「受信を開始」を押してマイクを許可します。
3. 送信側で短いメッセージを書き、「音で送信」を押します。
4. 受信側に本文が表示されます。ループ送信を使う場合も、受信側は同じメッセージを一度だけ表示します。

受信にはHTTPSまたはlocalhostが必要です。ページを前面に開き、端末のスピーカーとマイクを利用できる状態にしてください。受信側は送信開始前に待機させます。送信側では受信中の復号を一時的に止めるため、同時送受信ではなく交互に通信します。

## 音響プロトコル

各レーンは隣り合う2つの周波数を持ち、低い方を0、高い方を1として読みます。各レーンの発音開始を少しずつずらして重ね、発音後の無音区間で短い反響を逃がします。

- 4レーン、1シンボルあたり4ビット
- 5つの周波数バンクから送信側が選択。初期値は880/1080、1480/1680、2080/2280、2680/2880 Hz
- 1シンボルの初期値は64 ms。48〜96 msに調整でき、受信側は同期プリアンブルから速度と周波数バンクを自動判定
- 発音時間、レーンずらし、波形、全体音量、各レーン音量、音の立ち上がり・立ち下がり、左右バランスなど20項目を送信側で調整
- 同期プリアンブルは16シンボル。フレームにヘッダー、salt、IV、本文、CRC-32を含む

理論上の本文速度は64 ms設定で約7.8 bytes/s、最速48 ms設定で約10.4 bytes/sです。暗号化とフレーム情報が加わるため、512バイトの本文は初期設定で約74秒、最速設定で約56秒かかります。実際の所要時間はブラウザーや音響環境で変わります。送信側は受信確認を受け取らないため、受信欄で到着を確認してください。

連続ループは同じ暗号化フレームを繰り返し再生します。受信側はフレームIDで30分間重複表示を抑えます。再送間隔とゆらぎ、送信回数、最大ループ時間を設定できます。無音区間、レーンずらし、音のフェード、CRC-32は短い反響やノイズの影響を抑えたり検出したりするための工夫です。長い反響を消すエコーキャンセルや誤り訂正符号は実装していないので、受信に失敗する場合は距離や音量を調整して再送してください。

## 暗号化

暗号化は初期状態で有効です。Web Crypto APIを使い、パスフレーズからPBKDF2-SHA-256（180,000回）でAES-256-GCM鍵を導出します。メッセージごとにランダムな16バイトsaltと12バイトIVを生成し、認証タグ付きで暗号化します。フレームヘッダーは追加認証データとして保護します。

合言葉は音に載せず、別の安全な手段で相手に伝えてください。8文字以上で動作しますが、辞書にない長いフレーズを推奨します。合言葉の交換や相手の本人確認はこのアプリの範囲外です。暗号化を無効にすると本文は暗号化されず、CRC-32は偶発的な破損検出だけを行います。

## プライバシー

このページは入力文や合言葉をサーバーに送りません。音声はブラウザー内で処理し、受信履歴はタブを閉じると消えます。GitHub Pagesから取得するのは静的なHTML、CSS、JavaScriptだけです。Web Crypto APIの概要は[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)、音声処理は[W3C Web Audio API](https://www.w3.org/TR/webaudio-1.0/)を参照してください。

## 制約

- 512 UTF-8 bytesまでのテキスト専用です。ファイル転送、ACK、受信失敗時の自動再送、前方誤り訂正、鍵交換はありません。
- CRC-32は暗号ではありません。改ざん防止にはAES-GCMを有効にし、強い合言葉を使ってください。
- ノイズ抑制とエコーキャンセルを無効にしてマイクを開きます。端末やブラウザーによって対応が異なります。
- 反響が長い部屋、スピーカー音量が小さい環境、マイクの自動処理、周囲に他の音がある環境では受信に失敗することがあります。
- 送信完了は音を再生し終えた意味であり、相手が受け取った保証ではありません。

このプロジェクトは通信方式の学習用プロトタイプです。機密性や到達性を保証する用途には使わないでください。

## ローカルで開く

ファイルを直接開く代わりに、localhostで静的ファイルを配信してください。任意のローカルHTTPサーバーでこのフォルダーを公開し、ブラウザーでlocalhostのURLを開きます。公開時はGitHub ActionsのPagesワークフローを使います。リポジトリのSettingsでPagesのsourceをGitHub Actionsに設定すると、mainへのpushで自動公開されます。GitHub Docs: [custom workflows for GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
