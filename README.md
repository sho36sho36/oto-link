# OTO LINK

音の高さを使って、近くの端末どうしで短いテキストを送受信する実験的な音響モデムです。4つのFSKレーンを同時に鳴らし、1シンボルで4ビットを運びます。

## 使い方

1. GitHub Pagesでページを開き、送信側と受信側の両方で同じ合言葉を入力します。
2. 受信側で「受信を開始」を押してマイクを許可します。
3. 送信側に短いメッセージを書き、「音で送信」を押します。
4. 受信側の受信欄に本文が表示されます。

受信にはHTTPSまたはlocalhostが必要です。ページを前面に開いたまま、端末のスピーカーとマイクを利用できる状態にしてください。受信側は送信開始前に待機させます。送信側では受信中の復号を一時的に止めるため、同時送受信ではなく交互に通信します。

## 音響プロトコル

各レーンは2つの周波数を持ち、低い方を0、高い方を1として読みます。レーンごとの開始時刻を2ミリ秒ずつずらし、4音を重ねて再生します。

- レーン: 880/1080、1480/1680、2080/2280、2680/2880 Hz
- 1シンボル: 80 ms、音を出す時間は56 ms、残り24 msは無音
- 同期用プリアンブル: 16シンボル
- フレーム: マジック値、バージョン、暗号化フラグ、本文長、salt、IV、本文、CRC-32
- 受信: Web AudioのFFTで各周波数ペアの強さを比べ、プリアンブルでタイミングを合わせる

理論上のペイロード速度は約6.25 bytes/sです。暗号化とフレーム情報が加わるため、512バイトの本文ではおよそ1分半かかります。送信側は受信確認を受け取らないため、受信欄で到着を確認してください。

無音区間、同期プリアンブル、CRC-32で短い反響やノイズを検出しやすくしています。誤り訂正符号や反響除去は実装していないので、CRCが合わない場合は距離や音量を調整して再送してください。

## 暗号化

暗号化は初期状態で有効です。Web Crypto APIを使い、パスフレーズからPBKDF2-SHA-256（180,000回）でAES-256-GCM鍵を導出します。メッセージごとにランダムな16バイトsaltと12バイトIVを生成し、認証タグ付きで暗号化します。フレームヘッダーは追加認証データとして保護します。

合言葉は音に載せず、別の安全な手段で相手に伝えてください。8文字以上で動作しますが、辞書にない長いフレーズを推奨します。合言葉の交換や相手の本人確認はこのアプリの範囲外です。暗号化を無効にすると本文は暗号化されず、CRC-32は偶発的な破損検出だけを行います。

## プライバシー

このページは入力文や合言葉をサーバーに送りません。音声はブラウザー内で処理し、受信履歴はタブを閉じると消えます。GitHub Pagesから取得するのは静的なHTML、CSS、JavaScriptだけです。Web Crypto APIの概要は[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)を、音声処理は[W3C Web Audio API](https://www.w3.org/TR/webaudio-1.0/)を参照してください。

## 制約

- 512 UTF-8 bytesまでのテキスト専用です。ファイル転送、ACK、再送制御、前方誤り訂正、鍵交換はありません。
- CRC-32は暗号ではありません。改ざん防止にはAES-GCMを有効にし、強い合言葉を使ってください。
- ノイズ抑制とエコーキャンセルを無効にしてマイクを開きます。端末やブラウザーによって対応が異なります。
- 反響が長い部屋、低いスピーカー音量、マイクの自動処理、他の音がある環境では受信に失敗することがあります。
- 送信完了は音を再生し終えた意味であり、相手が受け取った保証ではありません。

このプロジェクトは通信方式の学習用プロトタイプです。機密性や到達性を保証する用途には使わないでください。

## ローカルで開く

ファイルを直接開く代わりに、localhostで静的ファイルを配信してください。任意のローカルHTTPサーバーでこのフォルダーを公開し、ブラウザーでlocalhostのURLを開きます。公開時はGitHub ActionsのPagesワークフローを使います。リポジトリのSettingsでPagesのsourceをGitHub Actionsに設定すると、mainへのpushで自動公開されます。GitHub Docs: [custom workflows for GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
